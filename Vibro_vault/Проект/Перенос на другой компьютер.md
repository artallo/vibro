# Перенос проекта на другой компьютер

Пошагово: как поднять проект на новой машине, где работает другой
Claude Code под другим аккаунтом, и продолжить работу без потери
контекста.

## Что переносится само, а что нет

| Что | Как переносится |
|---|---|
| Код, `config.toml`, README, `CLAUDE.md` | через git |
| Хранилище `Vibro_vault/` — вся база знаний | через git |
| Записи `tumen_results/` и `tumen_results_10k/` | через git |
| Записи `real_results/`, `results/` | **вручную**, их нет в git |
| `replay_results/`, `family_results/`, `stable_results/` | не переносить, пересчитываются скриптами |
| Память Claude Code с прошлой машины | не переносится; её содержимое продублировано в хранилище |

Невосстановимы только сырые `*_raw.npz`. Всё остальное считается заново.

## Шаг 1. На старой машине: проверить, что всё в репозитории

```bash
cd C:/Users/artal/Documents/Claude/vibro-analysis
git status --short
git log --oneline -1
```

Рабочая копия должна быть чистой, а ветка `main` совпадать с `origin/main`.
Если есть незакоммиченное, сначала закоммитить и влить.

## Шаг 2. На старой машине: собрать сырые записи, которых нет в git

Скопировать на флешку или в облако папку `real_results/` целиком, либо
только файлы `*_raw.npz` из неё и из `results/`, если там есть реальные
записи. Обычно это единицы мегабайт.

## Шаг 3. На новой машине: подготовить окружение

Установить Python 3.13 или новее и зависимости:

```bash
pip install numpy scipy matplotlib pyserial
```

Проверить, каким интерпретатором запускать:

```bash
python -c "import numpy, scipy, matplotlib, serial; print('ok')"
```

Если команда падает, значит пакеты стоят в другом Python, и запускать
скрипты нужно его полным путём.

## Шаг 4. На новой машине: клонировать репозиторий

```bash
git clone https://github.com/artallo/vibro.git vibro-analysis
cd vibro-analysis
```

Затем положить рядом скопированные на шаге 2 папки с сырыми записями.

## Шаг 5. Первое сообщение новому Claude Code

Открыть Claude Code в папке проекта и отправить примерно такой текст:

```text
Это проект анализа слабых вибраций зданий: ADXL355 на ESP32, пакеты по UART,
анализ на Python. Прочитай CLAUDE.md в корне, затем две заметки:
Vibro_vault/Развитие/Состояние проекта и передача контекста.md и
Vibro_vault/Главная.md. Дальше посмотри заметки в Vibro_vault/Скрипты/ по тем
скриптам, которых коснёмся.

После этого сделай три вещи:
1. Скажи, какой Python на этой машине содержит numpy, scipy, matplotlib и
   pyserial, и запусти тесты:
   python -m unittest test_stable_spectrum test_overview_figure test_family_analysis
2. Проверь, какие папки с данными есть на диске, и скажи, чего не хватает по
   сравнению с заметкой Vibro_vault/Данные/Где лежат данные.md.
3. Кратко перескажи своими словами состояние проекта и ближайший шаг, чтобы я
   убедился, что контекст восстановлен.

Порт датчика в config.toml с прошлой машины, его нужно поправить под эту.
```

## Шаг 6. Проверить, что контекст восстановлен

Ответ помощника должен содержать:

- что в полосе 0,5–15 Гц значимы только частоты записей 13.09: Y 1,73 Гц
  и X 1,97 Гц, и что их нужно подтвердить новой записью;
- что в остальных днях в полосе только шум датчика;
- что выше полосы работает техника, 49,1 Гц во все дни;
- что ближайший шаг — повторная запись в точке 13.09 с проверкой
  заданных частот.

Если этого нет, попросить перечитать заметку о состоянии проекта.

## Шаг 7. Настроить машину под себя

- Поправить `port` в `config.toml` под COM-порт этой машины.
- При необходимости авторизовать `gh`, чтобы помощник мог сам открывать
  pull request: `gh auth login`.
- Открыть `Vibro_vault/` в Obsidian через «Open folder as vault».

## Шаг 8. Проверить работу на реальных данных

```bash
python stable_spectrum.py tumen_results_10k/20260913_194837_ODR250_run01_raw.npz --band 0.5 100
```

Ожидаемый результат: значимые Y 1,73 Гц, X 1,97 Гц, Z 37 Гц. Если
получилось то же самое, перенос удался.

## Про память Claude Code

Файлы памяти помощника лежат вне репозитория, у каждого аккаунта и
компьютера свои. Переносить их не нужно: всё существенное из них
продублировано в этом хранилище. Новый помощник заведёт свою память сам.

Если всё же хочется перенести, файлы лежат в профиле пользователя, в
каталоге `.claude/projects/<путь к проекту через дефисы>/memory/`.
