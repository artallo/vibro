# stable_spectrum.py — устойчивый спектр

## Для чего

Отвечает на вопрос, у которого есть повторяемый ответ: какие пики записи
больше погрешности той спектральной оценки, которая их дала. Если ничего
не выделяется, отчёт так и пишет и называет предел в дБ, который был
нужен. Это тоже устойчивый результат. Метод описан в
[[Устойчивый спектр — метод]].

## Ключи

| Ключ             | По умолчанию                                                                                | Что делает                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `пути к .npz` или папка | обязательно | одна или несколько записей; папка — одна точка: берутся все `*_raw.npz` прямо в ней, по имени, подпапки нет (это другие точки) |
| `--output папка` | `stable_results/<запись>/` для одной записи, `stable_results/<имя папки>/runs/` для папки, с `--pool` — `stable_results/<имя папки>/pool/`, `stable_results/multi_<время>/` для нескольких файлов | куда писать                                                                |
| `--band MIN MAX` | из конфига, 0.2 15 | полоса анализа в Гц; для техники выше 15 Гц берите `0.2 100` |
| `--nperseg N …`  | из конфига, `2048`                                                                          | длины отрезков; каждая пишется в свою папку; `1024 2048 4096` — для сравнения, см. [[Разрешение nperseg]] |
| `--probe F …`    | нет                                                                                         | частоты, выбранные до этой записи: `2.88` — на всех осях, `Y:2.88` — только на Y; что стоит там, с честным порогом и верхней границей 95 %, см. ниже |
| `--probe-tolerance Гц` | 0.2 | насколько далеко от заданной частоты может стоять её пик; окно пробы ±это значение |
| `--probe-alpha` | 0.01 | вероятность ложного «present» для `--probe` и `--confirm-from`, независимо от `--alpha` поиска |
| `--min-distance Гц` | из конфига, 1 | пики ближе этого сливаются, если между ними нет провала; свой ключ `[stable_spectrum] min_distance_hz`, старый детектор его не читает |
| `--separation-sigma K` | из конфига, 2 | близкий более слабый пик остаётся, если провал до сильного глубже K погрешностей; 0 — сливать всегда, как до 02.10.2026 |
| `--pool` | нет | считать указанные записи прогонами одной точки и разобрать как одну длинную запись: каждый прогон режется сам, отрезки всех идут в одно усреднение; у каждого пика пометка «k/N» — в скольких прогонах его находит поиск по одному прогону |
| `--confirm-from ПУТЬ …` | нет | `stable_frequencies.csv` или папки с ними от поиска на других прогонах (обычно `--alpha 0.05`): их пики проверяются на этих записях как заранее заданные частоты |
| `--alpha`        | 0.01                                                                                        | допустимая вероятность хотя бы одного ложного пика на всю полосу и все оси; `0.05` — режим поиска, кандидаты, а не результат. Таблица порогов, пример и как пользоваться: [[Порог alpha и проверка половинами]] |
| `--baseline-window Гц` | из конфига, 10 | ширина скользящей медианы базы; `5` повторяет разборы до 01.10.2026, см. [[Устойчивый спектр — метод]] |

## Примеры

Одна запись, по умолчанию при 2048:

```bash
python stable_spectrum.py results/20260916_193930_ODR250_run01_raw.npz
```

Все прогоны одной точки: достаточно дать папку. Каждый прогон
разбирается отдельно, результат в `stable_results/<имя папки>/runs/`, с
`--pool` рядом в `pool/`. Внутри, как всегда, `nperseg_<n>/` и
`figure_compare_*`, даже при одном разрешении:

```bash
python stable_spectrum.py "tumen_results/260913 Тюмень, 10k"
python stable_spectrum.py "tumen_results/260916 Тюмень, три прогона" --band 0.5 100 --output stable_results/260916_wide
```

Если в папке не записи, а папки точек (например, папка здания
Республики 40), скрипт отказывается и перечисляет точки внутри. Список
файлов, как раньше (`"папка/"*_raw.npz`), тоже работает.

Проверка заданных частот, на всех осях или на одной:

```bash
python stable_spectrum.py results/<запись>_raw.npz --probe 0.62 1.60 11.35
python stable_spectrum.py results/<запись>_raw.npz --probe Y:2.88 X:2.49
```

Прогоны одной точки как одна запись:

```bash
python stable_spectrum.py "tumen_results/260913 Тюмень, 10k" --pool
python stable_spectrum.py <прогон 1>_raw.npz <прогон 2>_raw.npz --pool --output stable_results/<точка>_pooled
```

Результат называется `pooled_<время прогона 1>_<время прогона 2>`. Без
`--output` папка — `stable_results/<имя папки>/pool/`, если дана папка, и
`stable_results/pooled_<дата_время>/`, если даны файлы.

Поиск на одном прогоне и подтверждение на другом:

```bash
python stable_spectrum.py <прогон 1>_raw.npz --alpha 0.05 --nperseg 2048 --output stable_results/<точка>_r1_search05
python stable_spectrum.py <прогон 2>_raw.npz --nperseg 2048 --confirm-from stable_results/<точка>_r1_search05 --output stable_results/<точка>_r2_confirm
```

Подробно о схеме в [[Устойчивый спектр — метод]], раздел «Заданные
частоты и подтверждение».

Три разрешения для сравнения, узкая линия или широкая:

```bash
python stable_spectrum.py results/<запись>_raw.npz --nperseg 1024 2048 4096
```

## Что пишет

```
stable_results/<запись>/
├── comparison.txt                 сводка разрешений
├── figure_compare_<запись>.png    спектры разрешений наложены (при одном — один)
└── nperseg_2048/                  по умолчанию; с --nperseg 1024 2048 4096 — три папки
    ├── stable_report.txt          отчёт
    ├── stable_frequencies.csv     таблица значимых пиков
    ├── stable_probes.csv          пробы и подтверждения, если они были
    ├── figure_dominant_<запись>.png        картинка для показа
    └── figure_stable_spectrum_<запись>.png превышение в дБ против полосы шума
```

## Как читать отчёт

| Строка | Смысл |
|---|---|
| `Resolution` | nperseg, ширина бина, сколько отрезков усреднено |
| `Significance threshold: z >= …` | порог значимости; рядом `Each half (Persistent): z >= …` — порог, который пик должен пройти в каждой половине, см. [[Порог alpha и проверка половинами]] |
| `Recording check` | уровень по осям, выбросы в пакетах, скачки на стыках пакетов, разброс частоты опроса, исключён ли стартовый пакет |
| `Band edges` | появляется, только если у края полосы есть значимая структура, которую нельзя показать как пик: сразу за границей или в самом нижнем доступном бине |
| `Detection limit` | какое превышение в дБ было бы нужно, чтобы пик признали |
| `Strongest candidate` | самый высокий кандидат, если ничего не прошло порог |
| Частота пика | вершина, уточнённая параболой через три соседних бина; точнее центра бина, который может ошибаться на половину шага. Центр бина есть только в CSV, колонка `bin_frequency_hz` |
| Таблица пиков | частота, превышение, погрешность, z, z на половинах, `Persistent`; при `--pool` ещё `Runs` |
| `Pooled record of N runs` | при `--pool`: какие прогоны объединены и сколько в каждом пакетов; строка с `!`, если средний уровень оси между прогонами отличается больше чем в 20 раз против шума отсчёта — датчик, скорее всего, переставляли; `Recording check` идёт по каждому прогону отдельно |
| `Runs`, «1/2» на графиках | при `--pool`: в скольких прогонах частоту находит слепой поиск по одному этому прогону, на той же оси в пределах 0,2 Гц. Не проба на частоте объединённой записи: её выбор уже опирался на тот же прогон |
| `Support` на картинке | в скольких из 16 независимых окон частота видна; случайно набирается около 0,8 |
| `Requested frequencies` | ответ на `--probe`: окно, число бинов в окнах, честный порог и для сравнения порог слепого поиска; по каждой частоте «present» или «absent above X dB» |
| `Confirmation of … candidate(s)` | ответ на `--confirm-from`: откуда кандидаты, честный порог, «confirmed» или «not confirmed, above X dB», и в какой записи каждый кандидат был найден. Если запись сама входит в те, где кандидаты нашли, раздел пишет `skipped` |
| Зелёный кружок на `figure_dominant` | заданная или подтверждённая частота, прошедшая честный порог, но не слепой; красный крест — пик слепого поиска |

`Persistent = yes` значит, что пик виден в обеих половинах записи, которые
не делят ни одного отсчёта. Пик с `no` на графике подписан «(one half only)»:
это кандидат, а не результат, разбор с примером в [[Порог alpha и проверка половинами]].

> [!important] Честный порог для заданных частот — с 02.10.2026
> Пробы и подтверждения судятся порогом, который учитывает только бины в
> их окнах ±0,2 Гц, а не всю полосу: при 2048 и одной частоте на одной оси
> около 2,9–3,1 вместо 4,1. Так можно только для частот, выбранных **до
> этой записи**: с другого прогона, этажа или прибора. Частоту, найденную
> на этой же записи, так проверять нельзя — перебор спрятался бы, и
> ложных находок стало бы как у слепого поиска с низким порогом. Поэтому
> `--confirm-from` отказывается подтверждать запись её собственными
> находками. До 02.10.2026 пробы судились полным порогом в окне ±0,5 Гц,
> и соседняя сильная форма отвечала за пробу.

## Проверка записи

- **Выброс в пакете**: пик больше 12 робастных сигм. В пакете 1 это
  стартовый переход датчика, в остальных — удар.
- **Стартовый пакет исключается из спектров.** Если в пакете 1 есть выброс,
  спектры считаются без него, а отчёт пишет об этом строкой в `Recording
  check`. Иначе переход датчика от 0 к 1 g поднимает самый нижний бин на
  12–21 дБ и изображает структуру там, где её нет.
- **Громкие пакеты**: мощность в полосе больше медианы в 8 раз.
- **Тихая ось**: уровень меньше 5 % от самой громкой, проверьте провод.
- **Разброс частоты опроса** больше 1000 ppm: частоты размываются.
- **Скачок на стыке пакетов**: сбой или потеря отсчётов. Тихую потерю
  пакета в шумовой записи так не увидеть, отчёт об этом пишет.
