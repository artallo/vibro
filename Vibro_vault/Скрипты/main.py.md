# main.py — запись с датчика и повторный разбор

## Для чего

1. **Запись.** Читает пакеты `VIB2` из COM-порта, группирует их в сессии,
   пишет текстовый отчёт, два графика и сырые данные `_raw.npz`.
2. **Повторный разбор (replay).** Берёт готовый `_raw.npz` и прогоняет
   старый детектор на разных виртуальных раскладках сессий, без датчика.

Сырые данные `_raw.npz` — главное, что даёт этот скрипт. Его собственный
детектор и графики — старый вид анализа с фиксированными порогами, см.
[[Почему результаты скачут]]. Для результата используйте
[[stable_spectrum.py]].

## Ключи

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `--odr` | из конфига, 250 | частота опроса: 250, 125 или 62.5 (62 тоже понимается как 62.5) |
| `--packets-per-session` | из конфига, 8 | пакетов в одной сессии |
| `--min-recommended-sessions` | из конфига, 32 | сколько сессий записать, после этого запись останавливается; раскладка записи должна быть в таблице текущего режима, иначе отказ до подключения к датчику |
| `--repeat N` | 1 | записать N прогонов подряд: `run01`, `run02` … |
| `--replay путь.npz` | нет | повторный разбор готовой записи вместо записи с датчика |
| `--show` | нет | только с `--replay` и `--virtual-mode` с одной раскладкой: разобрать все виртуальные прогоны раскладки и открыть `figure2` в одном интерактивном окне, файлы не пишутся, см. ниже |
| `--virtual-mode …` | `all` | раскладки при replay, можно несколько сразу. Только из таблицы текущего режима в `config.toml`: при 2048 — `8x32 8x16 8x8 16x16 16x8`, при 1024 — `4x4 4x8 4x16 4x32 4x64 8x4 8x8 8x16 8x32`; `all` — все раскладки режима. Раскладку не из таблицы `main.py` отвергает |
| `--nperseg N` | из конфига, `[welch] nperseg` = 2048 | режим старого детектора на этот запуск: 1024 или 2048; нужна секция `[old_detector.nperseg_N]`, см. [[Старый детектор при 2048 — пороги по раскладкам]] |
| `--config путь` | `config.toml` рядом с `main.py` | другой файл настроек |
| `--replay-root папка` | `replay_results` | куда replay пишет папку записи |

`--repeat` нельзя сочетать с `--replay`.

Раскладка `AxB` означает A пакетов в сессии и B сессий. Например `8x32`
это 256 пакетов, то есть вся стандартная запись одним окном.

## Примеры

Стандартная запись, около 17 минут, 256 пакетов:

```bash
python main.py --odr 250 --packets-per-session 8 --min-recommended-sessions 32
```

Три прогона подряд, как 16.09.2026:

```bash
python main.py --odr 250 --packets-per-session 8 --min-recommended-sessions 32 --repeat 3
```

Повторный разбор записи во всех раскладках режима по умолчанию (2048) и
в прежнем режиме 1024:

```bash
python main.py --replay "results/20260916_193930_ODR250_run01_raw.npz"
python main.py --replay "results/20260916_193930_ODR250_run01_raw.npz" --nperseg 1024
```

## Что пишет

Запись, в папку `results/`:

| Файл | Содержимое |
|---|---|
| `<дата>_<время>_ODR250_runNN.txt` | отчёт старого детектора: кластеры частот по сессиям, «доверенные» области |
| `…_figure1.png`, `…_figure2.png` | графики старого детектора |
| `…_raw.npz` | сырые пакеты, см. [[Формат raw npz]]; сохраняется, только если запись дошла до заданного числа сессий |

Replay, в папку `replay_results/<имя записи>/nperseg_<n>/` (до 03.10.2026
без папки режима): подпапка на каждую раскладку и каждый виртуальный
прогон со своим `result.txt` и картинками, плюс `replay_runs.csv`,
`replay_regions.csv`, `replay_metadata.txt`. Каждый виртуальный прогон —
отдельный разбор; сводки «в скольких прогонах частота принята» здесь нет,
её даёт [[control_run.py]] `--old-detector`. `result.txt` и
`replay_metadata.txt` пишут режим и применённый порог `Med.Prom`.
`Med.Freq` и частоты кандидатов пиков с 03.10.2026 уточнены параболой,
решения детектора остаются на центрах бинов; подписи частот на графиках с
сотыми, см. [[Старый детектор — как он устроен]]. С 04.10.2026 на осях без
доверенных частот `result.txt`, `figure2` (полые кружки) и
`replay_candidates.csv` показывают до двух кандидатов ниже порога. Таблицы
читает [[family_analysis.py]]: ему передаётся папка режима.

## Интерактивный figure2

С 04.10.2026 `figure2` можно смотреть в окне:

- **в конце живой записи** (одиночный прогон) открывается только
  `figure2`; `figure1` сохраняется в PNG без окна;
- **по любой сохранённой записи** — `--show`:
  ```bash
  python main.py --replay "<папка точки>/<запись>_raw.npz" --virtual-mode 8x16 --show
  ```
  Разбор всех виртуальных прогонов раскладки считается заново из
  `_raw.npz`, файлы не пишутся. `--show` без `--virtual-mode`, с `all` или
  с несколькими раскладками — отказ.

В окне:

- **список «Run»** в панели инструментов выбирает виртуальный прогон, если
  их несколько (8×16 — два, 8×8 — четыре);
- **галочки X, Y, Z** скрывают и показывают оси, оставшиеся растягиваются
  на всё окно;
- **подсказка при наведении**: у кривой — частота и уровень ближайшей
  точки; у крестика доверенной частоты или кружка кандидата — `Med.Freq`
  и центр бина, `Freq` и диапазон пиков сессий, поддержка, `Med.Prom` и
  порог раскладки, `Band.Contr` и вес;
- панель инструментов сверху, из кнопок matplotlib оставлены «Домой» и
  «Сохранить»; окно подписано именем записи, раскладкой и режимом.

Список и галочки встраиваются в окно Tk (бэкенд TkAgg). При другом
бэкенде прогоны переключаются клавишами ← →, оси — клавишами x, y, z.

Подписи пиков на `figure2` — частота и поддержка, без дБ (с 04.10.2026);
`Med.Prom` виден в подсказке и в `result.txt`. Над самой высокой вершиной
панели оставлен запас по высоте, чтобы подписи не наезжали на заголовок.

| Раскладка | Пакетов | Время |

## Известные ограничения

- Номер пакета `sequence` из заголовка читается, но в `_raw.npz` не
  сохраняется. Поэтому по файлу нельзя доказать, что пакеты не терялись.
  Задача в работе, см. [[Открытые задачи]].
- Первый пакет записи содержит стартовый переход датчика: Z идёт от 0 к 1 g.
  Окно Ханна его подавляет, [[stable_spectrum.py]] отмечает его в проверке
  записи.
