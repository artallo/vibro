# Порог alpha и проверка половинами

Как ключ `--alpha` в [[stable_spectrum.py]] превращается в порог, что он
меняет и чего не меняет, и что значит пометка «one half only» на графике.
Общая схема метода — в [[Устойчивый спектр — метод]].

## Что такое alpha

alpha — допустимая вероятность того, что в записи чистого шума появится
**хотя бы один** ложный пик, на всю запись сразу: на все бины полосы и все
три оси. По умолчанию 0,01: на чистом шуме датчика в одной записи из ста
где-то вылезет один ложный пик.

Порог строится в два шага:

1. alpha делится на число проверяемых бинов (поправка Бонферрони). При
   2048 и полосе 0,2–15 Гц это 360 бинов, по 120 на ось.
2. Берётся квантиль распределения Стьюдента с числом независимых
   отрезков записи, у прогона из 256 пакетов около 241.

Порог из отчёта `stable_report.txt`, прогон 1 записи 13.09, 2048:

| alpha | Порог z | Порог половины | Предел обнаружения | Смысл |
|---|---|---|---|---|
| 0,001 | 4,65 | 2,38 | 1,26 дБ | очень строго |
| **0,01** | **4,10** | **2,10** | **1,11 дБ** | по умолчанию, результат |
| 0,05 | 3,69 | 1,89 | 1,00 дБ | режим поиска |
| 0,1 | 3,50 | 1,79 | 0,95 дБ | |

Порог меняется слабо: alpha в пять раз больше, с 0,01 до 0,05, а порог ниже
всего на 0,4 z. Поправка на 360 бинов уводит его далеко в хвост
распределения, а там хвост крутой.

## Что меняется, а что нет

- **Не меняются** частота, z и превышение в дБ каждого пика. Это свойства
  спектра, alpha на них не влияет.
- **Меняется** только то, какие пики попадают в список (z не ниже порога),
  и вместе с порогом — предел обнаружения в дБ: порог, умноженный на
  погрешность. При 0,05 он примерно на 10 % ниже, видны чуть более слабые
  линии.

## Что даёт alpha 0,05 на контрольных точках

[[control_run.py]] `a05 --alpha 0.05` против `base` (0,01), все семь
[[Контрольные точки|контрольных точек]], 02.10.2026:

```text
Kept 64, lost 0, new 11.
```

- Все 64 прежних пика остались с тем же z: мягкий порог только добавляет.
- 11 новых, все слабые, z 3,7–4,1, то есть сразу под порогом 4,10: на
  лестнице 2 Республики 40 X 9,4–9,8, X 11,85, Y 12,95, X 14,81 Гц; на
  лестнице 1 Y 5,20 Гц в прогоне 1 и Z 9,51 Гц в прогоне 2; на Малкова 23
  Z 3,52 Гц в одном прогоне из трёх.
- Почти все не повторяются: в объединениях пометки 0/2, 0/3, 1/2.
- Записей в прогоне 22 (16 прогонов и 6 объединений). Чистый шум при 0,05
  дал бы около одного ложного пика на все. Новых больше, значит часть —
  настоящие слабые колебания, но какие именно, по одной записи не сказать.

**Итог: alpha 0,05 даёт кандидатов, а не результат.**

## Как пользоваться

1. **Обычный разбор — alpha не трогать.** 0,01 — это то, что идёт в выводы.
   ```bash
   python stable_spectrum.py "tumen_results/260913 Тюмень, 10k"
   ```
2. **Поиск на одном прогоне, подтверждение на другом**, основная схема для
   слабых линий, подробно в [[Устойчивый спектр — метод]], раздел
   «Заданные частоты и подтверждение»:
   ```bash
   python stable_spectrum.py "<точка>/<прогон 1>_raw.npz" --alpha 0.05 --output stable_results/<точка>_r1_search05
   python stable_spectrum.py "<точка>/<прогон 2>_raw.npz" --confirm-from stable_results/<точка>_r1_search05 --output stable_results/<точка>_r2_confirm
   ```
   Прогон 1 предлагает кандидатов. Прогон 2 проверяет только их, честным
   порогом по бинам около этих частот (около 3,0–3,3 вместо 4,10). Строгость
   подтверждения задаёт `--probe-alpha` (0,01), он от `--alpha` не зависит.
3. **Что даёт мягкий порог на всех точках:**
   ```bash
   python control_run.py a05 --alpha 0.05
   python control_run.py --compare base a05
   ```
4. **Сводная картинка в режиме поиска**, [[overview_figure.py]]
   `--alpha 0.05`: пики, прошедшие только мягкий порог, — полые кружки и
   `search only` в выводе.

> [!warning] Оговорки
> - `stable_spectrum.py` пики, прошедшие только мягкий порог, **не
>   помечает**: при `--alpha 0.05` они выглядят как остальные, alpha видна
>   только в шапке отчёта и в строке `Significance threshold`. Такой отчёт
>   нельзя смешивать с обычными.
> - alpha не подбирают под нужную частоту: это настройка по шуму. Для
>   частоты, известной заранее, есть `--probe` с честным порогом.
> - Выше 0,05–0,1 смысла мало: порог опускается медленно, а ложных пиков
>   становится пропорционально больше.

## Проверка половинами: «one half only»

Запись делится на две половины, но **не по времени** «первая и вторая»:
неперекрывающиеся отрезки идут через один, чётные в одну половину, нечётные
в другую. Обе половины покрывают всю запись от начала до конца и не делят
ни одного отсчёта.

В каждой половине пик считается заново, получается два z, в отчёте колонка
`half z`, например `8.2/10.4`. Настоящая устойчивая линия есть в обеих
половинах примерно одинаково, и её z в каждой не ниже порога половины:
полный порог, умноженный на множитель меньше единицы (в половине меньше
отрезков, погрешность больше). Порог половины напечатан в отчёте рядом с
основным: `Each half (Persistent): z >= …`.

Пик, прошедший порог всей записи, но не прошедший порог хотя бы в одной
половине, остаётся в списке с `Persistent = no`. На графиках
`figure_stable_spectrum_*` под его вершиной стоит подпись
**«(one half only)»**, в сводке [[control_run.py]] — звёздочка.

### Пример: Y 4,77 Гц, 13.09, три прогона вместе, alpha 0,05

```bash
python stable_spectrum.py "tumen_results/260913 Тюмень, 10k" --pool --alpha 0.05
```

Порог всей записи z ≥ 3,65, порог половины z ≥ 1,88.

| Пик | z | Половины | Persistent | Прогоны |
|---|---|---|---|---|
| Y 1,72 | 18,7 | 8,2 / 10,4 | yes | 3/3 |
| X 1,98 | 12,9 | 4,9 / 8,5 | yes | 3/3 |
| X 13,39 | 7,2 | 4,1 / 4,0 | yes | 2/3 |
| **Y 4,77** | **3,9** | **3,8 / 1,5** | **no** | **0/3** |

У Y 4,77 Гц сходятся все признаки шума:

- **Проходит только мягкий порог.** При alpha 0,01 порог объединения 4,06,
  и этого пика там нет.
- **Не держится на половинах.** Почти весь z набран в одной половине, во
  второй 1,5 < 1,88. Половины чередуются по 16 с, поэтому настоящая линия,
  даже прерывистая длиной в минуты, попала бы в обе; такой перекос больше
  похож на случайный выброс.
- **0/3.** Ни один из трёх прогонов сам по себе эту частоту не находит.

Вывод: не форма здания, а выброс шума, пропущенный мягким порогом.

> [!tip] Как читать
> Пик с «(one half only)» — только кандидат. В выводы он не идёт, пока не
> подтвердится в другом прогоне, например через `--confirm-from`. В CSV
> то же лежит в колонках `half_z_low`, `half_z_high`, `persistent`.
