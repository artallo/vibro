# Старый детектор — как он устроен

Это детектор внутри [[main.py]], на котором построены отчёты `.txt`,
режим replay и [[family_analysis.py]]. Его математику сознательно не
меняют. Результат он даёт нестабильный на слабых записях, см.
[[Почему результаты скачут]], но понимать его нужно: на его выходе
работает весь исследовательский слой.

## Цепочка обработки

```text
пакеты
→ сессия
→ process_session
→ SessionResult
→ build_aligned_psd_data
→ compute_statistics
→ find_psd_peaks

параллельно:
пики PSD по каждой сессии
→ кластеризация частот по сессиям
→ подтверждение по медианному PSD
→ объединение раздробленных кластеров
→ отбор доверенных частот
→ визуализация
```

Велч: измеренная fs, окно Ханна, `nperseg` и `noverlap` из
[[Конфигурация config.toml]], масштаб плотности.

## Кластеризация частот по сессиям

В каждой сессии независимо ищутся пики PSD с порогами полосы. Затем пики
объединяются по частоте:

- пики сортируются, центр кластера равен медиане участников;
- пик присоединяется, если расстояние не больше допуска частоты;
- от одной сессии в кластер идёт не более одного голоса, при конкуренции
  остаётся более выраженный пик.

Слабое место: жадная кластеризация может раздробить одну физическую
область или, при большом допуске, слепить слишком широкий кластер. При
допуске 0,50 Гц это было хорошо заметно.

## Подтверждение по медианному PSD

Для каждого кластера считается независимое свидетельство на медианном
спектре:

| Поле | Смысл |
|---|---|
| `Med.Freq` | положение локального максимума медианного PSD рядом с кластером |
| `Med.Prom` | топографическая выраженность этого максимума в пределах полосы |
| `Med.Contr` | контраст к локальному фону |
| `Band.Contr` | отношение пика к медиане всей полосы |
| `Med.Pass` | старый порог выраженности 1,8 дБ, доверенности не определяет |

## Freq и Med.Freq — разные величины

Это важно и легко перепутать.

- **`Freq Hz`** — центр повторяемости по сессиям. Отвечает на вопрос, где
  в среднем сидят повторяющиеся пики сессий.
- **`Med.Freq`** — положение спектрального максимума на медианном PSD.
  Отвечает на вопрос, где находится сам спектральный максимум.

Реально наблюдавшийся случай: `Freq` 3,41 Гц, `Med.Freq` 3,66 Гц,
диапазон 2,92–3,90 Гц, поддержка 7 из 8. То есть центр повторяемости
может заметно отличаться от максимума спектра.

Ни одну из двух величин нельзя объявить единственно правильной. Обе нужно
хранить и учитывать, в том числе в [[family_analysis.py]].

## Объединение раздробленных кластеров

Отдельный допуск, не путать с допуском кластеризации:

```toml
[analysis.frequency_cluster_consolidation]
median_frequency_tolerance_hz = 0.20
```

Объединение разрешено, если оба кластера в одной полосе, у обоих есть
свидетельство медианного PSD, их `Med.Freq` близки, наборы сессий не
пересекаются и общий разброс медианных частот не больше 0,20 Гц. Цепочек
объединений нет специально. Поддержка после объединения считается по
объединению уникальных сессий.

## Доверенная частота

Доверенность определяется ровно двумя условиями:

```text
поддержка >= 50 %
И
Med.Prom >= 1,55 дБ
```

Компенсации нет: очень высокая выраженность не заменяет слабую поддержку.
Такого правила в коде нет, и добавлять его без эксперимента не надо.

В отборе доверенных **не участвуют**: устойчивость мощности окна,
локальное отношение сигнал-шум, σf, `Band.Contr`, `Med.Pass` и старое
решение ACCEPT.

`Band.Contr` влияет только на визуальный вес области:

| Случай | Вес |
|---|---|
| не доверенная | 0,50 |
| доверенная, `Band.Contr` < 1 дБ | 0,70 |
| доверенная, `Band.Contr` ≥ 1 дБ | 1,00 |

## Устойчивость мощности окна

Старый критерий приёма пика:

```text
accepted = window_power_stability >= min_stability   # 4.1
```

Он сильно зависит от настроек сбора и размера окна интегрирования,
поэтому не может служить главным признаком физической моды. Оставлен для
совместимости и диагностики. Доверенной частотой он не управляет.

## Один допуск на пять применений

Значение `frequency_tolerance_hz` зависит от ODR: 0,40 при 250 Гц, 0,35
при 125 Гц, 0,25 при 62,5 Гц. Несмотря на имя секции, одно и то же число
применяется сразу в пяти местах:

1. кластеризация по сессиям;
2. привязка к медианному PSD;
3. ширина доверенной области на рисунке;
4. центральное исключение в локальном отношении сигнал-шум;
5. окно интегрирования устойчивости мощности.

Для отбора доверенных частот реально важны первые два. Эксперименты со
значениями 0,25 / 0,35 / 0,40 / 0,50 меняли это общее число во всех пяти
местах сразу, см. [[История экспериментов до 09.2026]]. Разделять допуск
по применениям сейчас нет экспериментальных оснований.

## Что не менять без нового эксперимента

- поддержку 0,50 и `Med.Prom` 1,55 дБ;
- порог `Band.Contr` 1,0 дБ для веса;
- допуски по ODR и допуск объединения 0,20 Гц;
- параметры Велча и выраженности;
- правила кластеризации, свидетельства и визуализации.

Узкое место проекта сейчас не в порогах детектора, а в том, как правильно
собирать результаты во времени. См.
[[Временные масштабы и нестационарность]].
