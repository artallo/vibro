# Открытые задачи

## Главная цель: повторяемость на каждом объекте

Главная цель проекта не конкретный объект, а повторяемость: на каждом
объекте повторная запись в другой день должна давать те же частоты. Частота,
найденная в одной записи или в прогонах одного вечера, остаётся кандидатом,
пока её не подтвердит независимая запись. Поэтому все объекты равноправны,
и повтор нужен на каждом. Частоты прошлой записи задаются в повторе через
`--probe`, а не ищутся заново.

      лучше при ветре, и проверить 0,71 и 0,78 Гц как заранее заданные
      частоты: `--band 0.1 15 --nperseg 4096 --probe 0.71 0.78 2.63 2.85`.
      Записать ориентацию осей датчика относительно здания. См.
      [[2026-09-19 Малкова 23, 25 этаж]].
- [ ] **Эрвье, 5 этаж.** Повторить в той же точке и проверить
      `--probe 1.75 1.96`. Линии 19.09 слабые, поддержка 3–6 окон из 16,
      поэтому повтор здесь особенно нужен. См.
      [[2026-09-19 Эрвье, 5 этаж из 10]].
- [ ] **Точка 13.09.** Повторить запись и проверить
      `--probe 1.73 1.97 13.5`. Сначала выяснить, где записаны данные 13.09
      из папки `tumen_results_10k`: частоты 1,73 и 1,97 Гц подходят
      10-этажному зданию, на первом этаже Эрвье 17.09 их нет. См.
      [[2026-09-13 Тюмень, 10k]], [[2026-09-17 Эрвье, 1 этаж из 10]].
- [ ] **Журнал к каждой записи**: место, этаж, точка, крепление, ориентация
      осей, погода, работающая техника. Без него повтор нельзя честно
      сравнить с первой записью. Шаблон в [[Как обрабатывать дальше]].

## Доработки анализа

- [ ] **Сохранять номера пакетов в raw npz.** Прошивка присылает
      `sequence` и `elapsed`, но [[main.py]] их отбрасывает, а сбойные
      чтения пропускает молча. Нужно сохранять `packet_sequence` и
      `packet_elapsed_us`, повысить версию формата, считать пропуски при
      записи и проверять разрывы в [[stable_spectrum.py]]. Старые файлы
      должны читаться. Задачу запускали 16.09.2026 в отдельной сессии, но в
      `main` она не попала: на 01.10.2026 в коде нет `packet_sequence`, и
      ветки с этой работой тоже нет.
- [x] **Пик в крайнем бине полосы не находился.** Исправлено 30.09.2026:
      спектр считается с запасом за границами полосы, и пик у края
      сравнивается с настоящим соседом. Если сильная структура стоит сразу
      за границей или в самом нижнем доступном бине, отчёт пишет
      предупреждение в разделе `Band edges`. См.
      [[2026-09-19 Малкова 23, 25 этаж]].
- [ ] **nperseg 8192 пропускает запись целиком** — низкий приоритет, только
      ручной режим: по умолчанию 8192 не считается. Окна поддержки по 16
      пакетов дают только 3 отрезка по 8192, и запись пропускается с
      сообщением о причине.

- [ ] **Честный порог для `--probe`.** Сейчас заданные частоты судятся по
      полному порогу Бонферрони по всей полосе. Для заранее выбранных
      частот порог должен учитывать только число проверок: около 3,1 для
      девяти проверок при alpha 0,01. См. [[Устойчивый спектр — метод]].
- [ ] **Окно базы для широких горбов.** Скользящая медиана 5 Гц съедает
      горбы шире 2–2,5 Гц. Нужен ключ или автоматический выбор, см.
      [[Разрешение nperseg]].
- [ ] **Мощность по полосе для широких структур**, вместо высоты одного
      бина.
- [ ] **Учёт прерывистых сигналов.** Горб 36 Гц включается на 17–25 %
      времени. Можно отмечать отдельно пакеты, где он есть, и анализировать
      их.
- [ ] **Предупреждение о близости к краю полосы**: кандидат 0,62 Гц сидит
      там, где у Z начинается рост шума 1/f.
