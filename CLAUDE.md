# Ориентировка для Claude Code

Проект: анализ слабых вибраций строительных конструкций акселерометром
ADXL355 на ESP32. Цель — находить собственные частоты здания и получать
повторяемый ответ при повторных измерениях.

## Прочитай это первым

Вся накопленная база знаний лежит в хранилище Obsidian `Vibro_vault/`,
на русском. Перед работой прочитай два файла:

1. `Vibro_vault/Развитие/Состояние проекта и передача контекста.md` —
   задача, сделанная работа, известные факты об объекте, проблемы, план,
   состояние репозитория.
2. `Vibro_vault/Главная.md` — оглавление остальных заметок.

Дальше по необходимости: заметка на каждый скрипт в `Vibro_vault/Скрипты/`
со всеми ключами командной строки, методы в `Vibro_vault/Методы/`,
измерения по дням в `Vibro_vault/Измерения/`, правила работы в
`Vibro_vault/Развитие/Философия и принципы.md`.

Когда появляются новые результаты, скрипты или ключи, обновляй
соответствующую заметку хранилища, а не только README.

## Рабочие правила проекта

- Прежде чем подбирать любой порог, проверь, проходит ли целевая частота
  предел обнаружения. Иначе настройка идёт по шуму.
- Никаких заранее зашитых частот здания в коде.
- Математику старого детектора в `main.py` не менять без новой
  экспериментальной причины. Список того, что не трогать, в заметке
  `Vibro_vault/Методы/Старый детектор — как он устроен.md`.
- Пустой ответ с названным пределом в дБ — это результат, а не неудача.
- Правку метода проверяй на контрольных точках: `python control_run.py
  before` до правки, `after` после, `python control_run.py --compare before
  after`. Список точек в `control_points.toml`.

## Окружение

- Нужны numpy, scipy, matplotlib, pyserial. На машине может быть
  несколько Python: проверь, в каком из них есть эти пакеты, и запускай
  скрипты именно им.
- На Windows при перенаправлении вывода в файл задай `PYTHONUTF8=1`,
  иначе падает на символе `σ`.
- Порт датчика задаётся в `config.toml`, на каждой машине он свой.
- Тесты: `python -m unittest test_stable_spectrum test_overview_figure
  test_family_analysis test_band_power test_false_alarm_check
  test_control_run test_main`.

## Данные

Все реальные записи лежат в git: `real_results/` и `tumen_results/`.
Исключены только `results/` (сюда пишет новая запись
и тут лежат синтетические файлы), `replay_results/`, `family_results/` и
`stable_results/`: их содержимое пересчитывается скриптами. Новую реальную
запись после разбора нужно перенести из `results/` в папку, которая
лежит в git, иначе она не переживёт перенос на другую машину.

Нижняя граница полосы анализа задаётся в одном месте, `config.toml`, и
общая для всех скриптов, включая старый детектор. С 30.09.2026 она 0,2 Гц:
при прежних 0,5 Гц и бине 0,25 Гц первая форма высокого здания около 0,7 Гц
попадала в крайний бин и не находилась. `stable_spectrum.py` по умолчанию
считает nperseg 2048 (`[stable_spectrum] nperseg` в `config.toml`); для
сравнения разрешений и узких низких форм задай `--nperseg 1024 2048 4096`.

Старый детектор `main.py` с 03.10.2026 работает в режимах: `[welch]
nperseg` выбирает секцию `[old_detector.nperseg_<n>]` (2048 по умолчанию,
1024 — как было), где у каждой раскладки свой порог `Med.Prom`,
откалиброванный на шуме. Replay строит только раскладки режима и пишет в
`replay_results/<запись>/nperseg_<n>/`. Новую раскладку или режим без
калибровки на шуме не добавляй. См.
`Vibro_vault/Методы/Старый детектор при 2048 — пороги по раскладкам.md`.
