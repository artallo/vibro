# Как обрабатывать дальше

План по итогам разбора [[2026-09-16 Тюмень, три прогона]] и
[[2026-09-12 Тюмень]]. Отметки показывают, что уже сделано.

## 1. Смотреть выше 15 Гц

- [x] Ключ `--band` есть в [[stable_spectrum.py]] и [[overview_figure.py]].
- [ ] Включать полосу до 100 Гц в каждый разбор новой записи.

При полосе 0,5–100 Гц линии 36 и 49 Гц 16.09 проходят порог в каждом
прогоне, z от 4,7 до 11,4 при пороге 4,39. Это устойчивый результат, но
он про технику, а не про здание. Его полезно знать, чтобы не путать с
формами здания и следить, когда техника работает.

```bash
python stable_spectrum.py results/<новая>_raw.npz --band 0.5 100
```

## 2. Проверить заданные частоты на новой записи

Кандидаты 16.09: **Z 0,62 Гц, Y 1,60 Гц, X 11,35 Гц**. Плюс 13,65 Гц
из записи 02.09.

```bash
python stable_spectrum.py results/<новая>_raw.npz --band 0.1 15 --probe 0.62 1.60 11.35 13.65
```

> [!warning] Поправка к прежнему совету
> Раньше было сказано, что с `--probe` порог падает с 3,9 до 2,4. Это
> неверно для текущего кода. `--probe` сейчас судит по полному порогу,
> около 3,9. Честный порог для заранее выбранных частот ниже: около 3,1
> для 3–4 частот на трёх осях при alpha 0,01. Пока доработки нет,
> смотрите в таблице `Requested frequencies` колонку `z` и сравнивайте с
> этим числом вручную. Доработка в [[Открытые задачи]].

Частоту считать подтверждённой, если она проходит порог на новой записи,
которая не участвовала в выборе частоты.

## 3. Если цель — само здание

Датчик в этой точке уже лучше паспорта. В полосе 0,5–15 Гц выжать больше
нечего. Остаются пути из [[Шум датчика и пределы обнаружения]]:

- [ ] **Длинная непрерывная запись около 8 часов**, например на ночь.
      Предел падает с 0,6 до 0,2 дБ, погрешность убывает как единица на
      корень из N. Для [[main.py]]: `--packets-per-session 8
      --min-recommended-sessions 896`, около 7168 пакетов.
- [ ] **Точка с большим возбуждением**: верхние этажи, ветреная погода,
      рядом с дорогой, рабочее время.
- [ ] **Датчик с шумом около 1 µg/√Гц**: сейсмоакселерометр или геофон.
- Два ADXL355 рядом со взаимным спектром дают только корень из двух. Не
  стоит усилий.

## 4. Мелкий бин для узких мод

- [x] [[stable_spectrum.py]] считает nperseg 1024, 2048 и 4096, каждое в
      свою папку. См. [[Разрешение nperseg]].
- [ ] На каждой новой записи сравнивать папки: узкая мода растёт от 1024
      к 4096, широкая структура держит высоту.

Мода с затуханием 1–2 % имеет ширину 0,05–0,1 Гц и в бине 0,25 Гц теряет
до 6 дБ высоты. На записях 12.09 и 16.09 разрешение ничего не открыло, но
для будущих записей это правильный режим.

## 5. Гигиена записи

- [x] Проверка записи в [[stable_spectrum.py]] ловит стартовый переход,
      удары и скачки на стыках пакетов.
- [ ] После записи читать раздел `Recording check`. Серии выбросов, как
      12.09 run03, означают шаги или работы рядом. Такие записи лучше
      повторить.
- [ ] Не трогать датчик и не ходить рядом во время записи.
- [ ] Записывать в журнал измерения место, этаж, погоду и работающую
      технику, см. шаблон ниже.

## Какие данные нужны для развития проекта

| Что | Зачем | Как получить |
|---|---|---|
| Длинная запись, 4–8 ч, одна точка | опустить предел до 0,2–0,3 дБ | `--min-recommended-sessions 448…896` |
| Дневная и ночная запись в одной точке | сравнить возбуждение | два запуска в разное время |
| Запись на верхнем этаже | больше амплитуда форм здания | перенести датчик |
| Запись в ветреный день | больше возбуждение | по погоде |
| Номера пакетов в файле | доказать непрерывность склейки | задача в [[Открытые задачи]] |
| Сведения о месте каждой записи | связать линии с техникой, а частоты с конструкцией | журнал измерения |
| Паспортные или расчётные частоты здания | знать, где искать | проект здания, расчёт |
| Запись при выключенной технике | отделить 36, 49, 60, 91 Гц от здания | договориться с эксплуатацией |
