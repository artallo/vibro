# repeatability_check.py — повторяемость на половинах записи

## Для чего

Делит запись на две половины без общих пакетов, анализирует каждую
отдельно методом [[stable_spectrum.py]] и сравнивает ответы. Это ближе
всего к вопросу «даст ли второе измерение ту же картину», если есть
только одна запись.

Два способа деления:

- **first/second**: первая и вторая половина по времени. Показывает,
  насколько здание было стационарным.
- **even/odd**: чётные и нечётные пакеты. Обе половины видят одно и то же
  возбуждение, поэтому расхождение здесь — нестабильность самой оценки.

С ключом `--replay-root` то же сравнение делается для старого детектора,
чтобы было с чем сравнить.

## Ключи

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `пути к .npz` | обязательно | записи |
| `--replay-root папка` | нет | папка с результатами replay для сравнения со старым детектором |
| `--alpha` | 0.01 | вероятность ложного пика |
| `--csv файл` | нет | сохранить таблицу сравнений |

## Пример

```bash
python repeatability_check.py real_results/*_raw.npz --replay-root replay_results
```

## Как читать

Сравнения, где обе половины ничего не нашли, считаются отдельно: повторить
пустой ответ ничего не стоит, и такие случаи завышают оценку.

На шести вечерних записях сентября 9 из 12 сравнений пустые с обеих
сторон. Из трёх содержательных совпало одно. Старый детектор набрал 0,20,
но он никогда не возвращает пустой ответ, поэтому числа напрямую не
сравниваются. Подробнее в [[Почему результаты скачут]].

Скрипт работает при nperseg 1024 из конфига: половины even/odd состоят из
несмежных пакетов, их нельзя склеивать в длинные отрезки.
